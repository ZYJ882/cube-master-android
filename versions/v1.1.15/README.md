# CubeMaster Android v1.1.15 — 快速查表加载修复版

**版本：** v1.1.15  
**项目：** 魔方大师 CubeMaster Android

## 问题修复

此前版本在 Android 新进程中首次触达两阶段求解器时，会在 Java 静态初始化块内重新建立所有坐标转移表和剪枝表。该过程在部分手机上会长时间占用后台线程，导致界面持续显示“正在初始化”，而用户无法得到明确结果。

本版本将同一套、已验证的 Kociemba 坐标表和剪枝表在构建期导出为版本化二进制资源 `kociemba_tables_v1.bin`，并随 APK 打包。运行时仅从 APK 的 `AssetManager` 打开、校验并加载该资源；不再在手机端重新生成完整表。Kociemba 的剪枝表用于提供搜索距离下界，从而在两阶段搜索中裁剪分支。[1]

| 场景 | v1.1.15 行为 |
|---|---|
| 应用冷启动 | 从 APK 内置资源加载坐标与剪枝表，不执行全表重建。 |
| 用户点击“计算高效解法”时资源未加载 | 保留当前请求，资源加载完成后自动执行当前状态的标准两阶段求解。 |
| 资源损坏、缺失或超过 8 秒未加载 | 中止等待并显示明确失败信息；可点击按钮重新加载，不会无限显示初始化。 |
| 当前魔方状态 | 仍只使用 Kociemba 两阶段算法计算当前完整、合法状态；不使用动作逆序替代。 |
| 还原动画 | 仅播放已计算并校验成功的标准记号解法。 |

> 本版内置资源约 4.2 MB。该体积用于换取手机端启动时不再重建数百万级坐标和剪枝表条目。

## 回归验证

在宿主 JVM 冷启动测试中，内置资源加载完成用时 **41 ms**；随后完成十组端到端两阶段求解验证：一组外层组合状态、一组含 `M/E/S` 中层转动并进行中心块朝向规范化的状态，以及八组固定随机种子的 22 步合法状态。每组从当前面片状态独立求解并精确回到复原态，解法长度为 18–23 步。

同时验证了截断资源会立即被拒绝，并返回“资源数据不完整或格式错误”；Android 工程已完成构建，APK 已验证 v2 签名，且内置资源已确认存在于 APK 中。
