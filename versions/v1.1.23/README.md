# CubeMaster Android v1.1.23

## 视角方向与 Roux / ZZ 阶段预热稳定版

本版同时修复连续纵向浏览引入的横向方向问题，以及真实 Roux / ZZ 第一次计算占满全局 `12` 秒保护的问题。

| 问题 | 修复 |
|---|---|
| 纵向越过顶面/底面后，横向（X 轴）拖动方向反转 | 相机仍保持无阈值纵向环绕；横向 yaw 增量、`3D` 外部拖动和惯性动画会根据当前俯仰方向自动校正符号，使左右拖动保持屏幕直觉。 |
| Roux 首次点击同步建立大型 Block 剪枝表 | 选择“真实 Roux”时即在后台预热；点击计算时若尚未准备完，只展示明确的准备状态，不进入 `12` 秒实际搜索保护；准备完后自动计算。 |
| ZZ/Roux 被无关的 Kociemba 查表门控 | 仅 Kociemba 与需要两阶段输入的入门层先法等待 Kociemba 资源。Roux、ZZ 使用各自独立的阶段表，不再等待该资源。 |
| 异常困难状态拖到全局 12 秒被强制停止 | Roux 与 ZZ 的实际阶段搜索设置 `7` 秒独立预算，先于界面全局保护返回清晰错误信息。 |

阶段表预热支持 Roux 与 ZZ 并行运行，防止用户从一种方法切换到另一种时排队等待。退出应用页面时，相关预热任务与执行器会被取消和关闭。

## 性能回归

在三组符合应用规则的合法 `22` 步打乱上完成了端到端验证。完成后台预热后，Roux 实际阶段搜索为约 `12–123 ms`；ZZ 为约 `778–1563 ms`（桌面回归环境）。每组均生成动作并完成主状态复原。首次 Roux Block 表构建约 `5.8 s`，现已从点击计算路径移至后台预热状态。

> 不同 Android 设备的绝对时间会不同；本版保证首次准备不再伪装成实际计算，也不再因无关 Kociemba 资源阻塞 Roux/ZZ。
