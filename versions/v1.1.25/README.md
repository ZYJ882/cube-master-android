# CubeMaster Android v1.1.25

## Roux 首次就绪资源加载修复版

本版处理真实设备上选择 Roux 后长期停留在“正在后台准备阶段剪枝表”的问题。该等待不是 Roux 动作规划本身，而是旧版在手机上首次使用时现场 BFS 构建四张大型 `1×2×3 Block` 精确距离表造成的。

| 项目 | v1.1.24 及之前 | v1.1.25 |
|---|---|---|
| Roux 首次预热 | 手机端运行时构建四张联合 Block 距离表；设备性能较低时可能长时间显示准备中。 | 四张表在构建期预生成，并作为 `roux_block_tables_v1.bin` 随 APK 发布。 |
| 表数据格式 | 运行时字节表与 BFS 队列，峰值内存和 CPU 开销较高。 | 每个距离压缩为 4-bit；资源包含格式版本、坐标键和尺寸校验。 |
| 首次手机行为 | 用户点击后等待大型 BFS 完成。 | 后台仅从 APK 读取并校验预生成资源；不会现场构建 Block 表。 |
| 求解阶段 | First Block → Second Block → CMLL → M/U LSE。 | 阶段目标、动作约束与主状态验证保持完全相同。 |

## 验证结果

生成器在构建环境中创建完整资源耗时约 `6.2 s`，生成后资源未压缩大小为 `15,925,840 bytes`，在 APK 中压缩为约 `3.95 MB`。从最终 APK 解出的资源与源资源 SHA-256 一致，并可由实际加载器成功读取。

| 检查 | 结果 |
|---|---|
| 从 APK 资源加载四张表 | `62 ms`（测试环境） |
| 加载后 30 组合法 35 步状态 | `30/30` 完成并复原主状态 |
| 加载后最大 Roux 阶段规划时间 | `324 ms`（测试环境） |
| Android Debug 构建 | 通过 |

> Android 设备实际读取时间会随存储与 CPU 不同而变化，但新版不再执行旧版的手机端大型 BFS 表构建，因此不会再长时间停留在“后台准备阶段剪枝表”。
