# CubeMaster Android v1.1.21

## 安全随机打乱验证版

本版针对“打乱是否真随机、还原是否只是动作逆放”完成代码审计并更新打乱熵源。

| 项目 | v1.1.21 行为 |
|---|---|
| **随机来源** | 使用 `java.security.SecureRandom`，由系统安全随机源提供熵。 |
| **打乱长度** | 每次固定生成 `22` 步外层转动。 |
| **合法动作** | 仅允许 `U/R/F/D/L/B` 及其 `2`、`'` 变体；每一步均由 `CubeState.applyMove()` 实际施加，因此状态必然是合法可还原状态。 |
| **序列约束** | 不允许连续同面，也不允许连续同轴的相对面，避免无效合并与不自然打乱。 |
| **还原来源** | 求解器只接收当前 `54` 面片快照。`lastScrambleMoves` 仅用于向用户显示本次打乱记录，不参与求解分派或播放列表生成。 |

Kociemba 路线由 `SolverFacade.solve(currentFacelets)` 对当前状态搜索动作；CFOP、Roux、ZZ 则各自从同一当前状态进入独立阶段内核。入门层先法会利用一个由当前状态求得的中间结果重建其独立层先法内核输入，但最终展示的阶段动作来自层先法状态机，不读取 UI 保存的打乱记录。

## 审计回归

对三组符合应用约束的固定 `22` 步合法面转进行了端到端审计。每组均通过 `SolverFacade.validate()` 可解性校验；Kociemba 生成的步骤均能将当前状态还原为标准复原状态，并且逐项比较后**不等于**该组打乱动作的逆序。该审计直接排除了“读取打乱记录后直接逆放”的路径。
