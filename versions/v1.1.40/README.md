# CubeMaster Android v1.1.40

## 求解串行隔离与资源清理版

本版针对“停止计算后，前一个解法是否仍在运算；立刻点击下一个解法会不会两者一起算”的稳定性问题进行了审计与修复。

## 实际求解隔离

| 项目 | v1.1.40 行为 |
|---|---|
| 实际求解执行器 | Kociemba、层先、CFOP、Roux、棱先、角先、ZZ 全部进入唯一的串行后台通道。 |
| 点击取消 / 切换方法 / 超时 | 当前 `Future` 接收 `cancel(true)`，请求代次递增，旧结果与旧进度回调失效。 |
| 启动下一解法 | 新任务只会排在串行通道上；它必须等待旧搜索检查中断并退出后才能开始，绝不与旧搜索并行占用 CPU。 |
| 两阶段搜索中断 | 两阶段主循环和第二阶段循环均检查线程中断。 |
| 分阶段搜索中断 | IDA* 的每个深度与每个 DFS 节点均检查中断和时限。 |

> `Future.cancel(true)` 在 Java 中是协作式取消：它会立刻设置中断标记；求解器在下一个中断检查点退出。CubeMaster 的实际搜索已在主循环或 DFS 节点检查该标记，因此不会继续完整跑完旧搜索。新任务为了保证不重叠，会等待旧线程退出，而不是冒险并行启动。

## 预热与内存资源

预热任务与实际求解分离：Kociemba、Roux、ZZ、棱先/角先的表加载或宏预组合可以独立后台进行，但它们不会作为用户点击后的“实际求解”与下一条解法并行搜索。Roux 块表和 Kociemba 坐标表是进程级静态缓存，属于有界、可复用的性能缓存，而非持续持有 Activity 的内存泄露。

Activity 销毁时会：移除主线程回调、取消当前实际求解、取消 Kociemba/Roux/ZZ/棱先角先预热 Future，并对全部执行器调用 `shutdownNow()`。相机识图对话框也拥有并在关闭时关闭自己的单线程执行器。
