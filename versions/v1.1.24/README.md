# CubeMaster Android v1.1.24

## Roux / ZZ 阶段规划可靠性修复版

本版修复了真实 ZZ 方法在部分合法状态上停留在计算界面、最后因阶段搜索上限失败的问题。问题的根因不是手机算力：在 EOLine、ZZ-F2L、OCLL 都完成后，少数合法 PLL 状态需要超过原先 `16` 步的受限 `R/L/U` 路径；一个可复现样本需要 `18` 步，原始 IDA* 搜索耗时超过移动端预算。

| 阶段 | v1.1.24 行为 |
|---|---|
| **EOLine** | 仍由独立搜索完成全棱定向与 DF/DB Line。 |
| **ZZ-F2L** | 仍仅使用 `R/L/U`，按底层十字和四组角棱对逐段构建并验证。 |
| **OCLL** | 仍仅使用 `R/L/U`，只完成最后层角块朝向并验证。 |
| **PLL** | 改为优先匹配独立的标准 PLL 算法表，枚举顶层 `U` 对齐与整体 `y` 旋转，并直接在主魔方状态验证整颗复原。表未匹配时才回退到独立阶段搜索。 |

该变更不调用 Kociemba 完整解，也不使用打乱动作逆序。PLL 案例表来自项目已纳入并标注 MIT 归属的 CFOP 内核，仅作为 **ZZ 的最后层排列阶段** 使用；EOLine、受限 F2L、OCLL 仍由 ZZ 自身阶段目标生成。

## 回归验证

在固定种子生成的 `120` 组合法 `35` 步外层打乱状态上执行了端到端回归；每组均同时调用真实 Roux 与真实 ZZ，执行输出动作并验证主 CubeState 回到标准复原状态。

| 方法 | 成功 | 失败 | 预热后观测到的最大规划时间 |
|---|---:|---:|---:|
| Roux | 120 | 0 | 337 ms |
| ZZ | 120 | 0 | 28 ms |

> 上述时间来自桌面回归环境，Android 设备绝对耗时会不同；关键保证是标准 PLL 表移除了先前深度 `18` 案例的搜索分支爆炸，且所有阶段仍在主状态上逐段验证。
